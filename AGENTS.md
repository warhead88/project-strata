# Работа над Project Strata

- Все крейты живут в `crates/`, наследуют `[workspace.package]` и включают `[lints] workspace = true`. Зависимости объявляй в корневом `Cargo.toml` и подключай через `.workspace = true`.
- Разделяй Rust-файлы по ответственности. Выделяй отдельный крейт, когда у подсистемы есть свой API и чёткое направление зависимостей. Держи общую логику в одном месте.
- Клиент отвечает за графику, UI и ввод. Правила мира помещай в библиотечные крейты, которые можно собрать и протестировать без Bevy, окна и GPU. Клиент читает состояние симуляции и передаёт ей команды.
- Держи редактируемые деревья контента в `content/`. Деление на файлы должно отражать предметную область, чтобы записи можно было находить и менять независимо. Для ссылок между записями используй стабильные идентификаторы.
- Начинай фичу с конкретного изменения поведения и определяй, какая подсистема отвечает за соответствующее правило. Вариант с уже известным поведением добавляй через данные. Новое правило реализуй у владельца состояния и используй его из всех затронутых путей. Расширяй публичный API, когда другому модулю нужна конкретная операция или результат. Выделяй общую абстракцию, когда можешь показать случаи её применения и объяснить, какая логика у них общая.
- Сохраняй принятые в тредах решения по подсистемам в `docs/`, чтобы следующие треды могли опираться на них.
- Выбирай входную точку по области задачи в [README](README.md#с-чего-начать-тред). Начинай с профильного решения, кода владельца и ближайшей проверки. Расширяй поиск по символам и вызовам, когда меняется контракт или нужно проследить его последствия. При передаче работы укажи ревизию, результат проверки и оставшийся открытый вопрос, если он есть.
- Проектируй крупные игровые области по отдельности. Для технического прототипа формулируй конкретный проверяемый вопрос и сохраняй требования к детализации полной игры.
- Размеры файлов проверяются командой `cargo limits`. Исходники ограничены 400 строками и 64 КиБ, конфиги — 250 строками и 32 КиБ, файлы в `content/` — 500 строками и 128 КиБ. При росте файла выделяй связную часть в отдельный модуль или файл данных.
- Перед завершением изменений запускай `cargo verify` из корня. Исключения для линтов оформляй локально с причиной.
